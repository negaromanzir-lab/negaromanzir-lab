Document-Aware AI Assistant & ChatBot (RAG Architecture)

A production-grade conversational AI assistant featuring Retrieval-Augmented Generation (RAG), combining semantic document embeddings in PostgreSQL (pgvector) with streaming LLM inference for grounded, hallucination-free querying.

RAG Vector Search PostgreSQL & pgvector Server-Sent Events (SSE) Multi-Format Ingestion

The Challenge

Commercial Large Language Models exhibit high conversational fluency but suffer from severe hallucinations when questioned on private company handbooks, legal contracts, or custom domain specifications. Simply pasting massive documents directly into prompts quickly overruns LLM context windows, inflates operational API costs, and incurs prohibitive latency.

The engineering challenge was to design an automated document ingestion and vector retrieval pipeline that dynamically extracts only the most semantically relevant text fragments and injects them as verified grounding context into the inference loop.

Architectural Design

The RAG architecture decouples document processing and semantic indexing from real-time query inference to achieve low-latency responses:

Ingestion Pipeline

Extracts clean text from uploaded PDFs, DOCX files, Markdown, and CSVs. Applies character normalization and sliding-window recursive chunking with token overlap.

Vector Engine (pgvector)

High-dimensional vector embeddings generated via OpenAI embedding models and indexed in PostgreSQL using cosine distance metrics for sub-second semantic similarity searches.

Streaming Engine (SSE)

Express server orchestrating top-k prompt augmentation and streaming LLM token streams over Server-Sent Events to provide instantaneous visual feedback in React.

The RAG Ingestion & Query Pipeline

Documents and conversational queries flow through a three-stage mathematical pipeline:

Phase 01

Ingestion & Chunking

  • Document upload & type verification
  • Text sanitization & extraction
  • Sliding-window token chunking
  • Document metadata attribution
Phase 02

Embedding & Indexing

  • Batch vector generation
  • PostgreSQL pgvector storage
  • Cosine distance indexing
  • Metadata linkage & versioning
Phase 03

Augmented Inference

  • User prompt vectorization
  • Top-k similarity chunk retrieval
  • Context-injected prompt synthesis
  • Real-time SSE token streaming

Key Technical Decisions & Challenges

1. Overlap-Preserving Chunking Strategy: Splitting text naively by raw line or paragraph breaks often severs sentences across boundaries, corrupting the semantic meaning of embeddings. By configuring a recursive character chunker with a 600-token window and a 100-token overlap, key contextual concepts remain intact across adjacent segments.

2. Minimizing Time-to-First-Token (TTFT) via SSE: Traditional synchronous HTTP request/response patterns force users to stare at loading spinners for seconds while the LLM generates a complete response. Implementing Server-Sent Events (SSE) allows the client to render each generated token incrementally as it emerges from OpenAI's streaming API.

3. Grounded Prompt Constraints & Attribution: To eliminate confident hallucinations, system instructions enforce strict grounding guardrails: if retrieved chunks lack the required facts, the assistant admits absence of data rather than guessing, and explicitly cites source document identifiers alongside every claim.
